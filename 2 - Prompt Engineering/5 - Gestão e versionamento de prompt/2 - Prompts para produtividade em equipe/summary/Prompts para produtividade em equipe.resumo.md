# Prompts para produtividade em equipe

## Prompt pessoal ou de equipe

Dentro dos prompts de produtividade, o professor separa dois casos: o prompt que fica só na máquina do desenvolvedor e o prompt usado pela equipe. A diferença muda a forma de trabalhar. Em equipe, o processo é iterativo: raramente uma pessoa define sozinha os prompts que todos vão usar. Vários desenvolvedores testam, tentam tirar o melhor do prompt e, assim, o time vai refinando. O prompt sempre evolui e pode variar conforme o modelo usado.

## Prompt como software, com Git

A recomendação é tratar o prompt como software e versioná-lo com Git. O professor monta uma sugestão a partir de conversas com desenvolvedores de grandes empresas, sem apresentá-la como verdade absoluta, porque cada time trabalha de um jeito. O fluxo: o prompt fica sob controle de versão, a equipe testa e discute, a mudança entra por pull request, outros desenvolvedores testam e fazem code review, e a versão aprovada vira o prompt principal do time.

## Avaliação subjetiva

Esses testes e revisões costumam ser subjetivos, mesmo com métricas. Prompts de produtividade são mais difíceis de avaliar de forma objetiva do que prompts usados em outros sistemas, porque o trabalho passa por muitas iterações e raramente sai pronto em um one-shot. Ainda assim, existem formas de fazer evaluation desses prompts, tema que a disciplina retoma mais adiante.
