# Gabarito — Prompts para produtividade em equipe

## 1. Tech lead define sozinho o prompt "definitivo" do time
**Correta: B**
**Por quê:** O professor diz que, em equipe, o processo é iterativo: raramente um único desenvolvedor define os prompts que todos vão usar. Vários devs testando e tentando tirar o melhor do prompt é o que faz o time refiná-lo, e o prompt sempre evolui. Declarar uma versão definitiva corta esse ciclo.
- **A:** O cenário é de prompt para a equipe, que a aula separa do prompt pessoal; a recomendação é compartilhar e versionar, não deixar cada um com a sua cópia.
- **C:** A aula diz o contrário: a avaliação de prompts de produtividade costuma ser subjetiva, mesmo com métricas, e não exige prova objetiva antes do uso.
- **D:** O Git é parte da recomendação, mas o fluxo também inclui testes da equipe, pull request e code review; só registrar não traz a iteração entre devs.
**Conceito:** processo iterativo de prompts em equipe

## 2. Por que avaliar prompts de produtividade é mais subjetivo
**Correta: C**
**Por quê:** O professor explica que esses prompts passam por muitas iterações: o software vai saindo aos poucos e raramente fica pronto em um one-shot. Por isso fica difícil avaliá-los de forma tão objetiva quanto prompts usados em outros sistemas.
- **A:** A aula afirma que existem formas de fazer evaluation inclusive de prompts para desenvolvimento.
- **B:** A variação entre modelos é real e foi citada, mas não é o motivo dado para a subjetividade, nem impede comparar versões.
- **D:** Meia-verdade: o professor diz que o processo é subjetivo "por mais que você queira colocar diversos tipos de métrica", ou seja, métricas podem ser usadas; e o motivo que ele dá para a subjetividade são as muitas iterações, não a opinião do revisor.
**Conceito:** subjetividade na avaliação de prompts de produtividade

## 3. Afirmação INCORRETA sobre o fluxo de equipe
**Correta: A**
**Por quê:** Meia-verdade: trocar de modelo pode, sim, exigir adaptação, mas a aula diz que o prompt sempre vai evoluir pelo processo iterativo da equipe, com vários devs testando e propondo mudanças por pull request. A versão principal continua sujeita a novos testes, não só a revisões motivadas por troca de modelo.
- **B:** Correta: o fluxo sugerido é fazer pull request e pedir que outros devs testem e façam code review antes de ir para produção.
- **C:** Correta: o professor diz que o prompt pode ter variações de acordo com o modelo utilizado.
- **D:** Correta: o professor compilou a sugestão de conversas com devs de grandes empresas e diz que não é verdade absoluta, porque cada time trabalha de um jeito.
**Conceito:** fluxo de versionamento de prompts em equipe
