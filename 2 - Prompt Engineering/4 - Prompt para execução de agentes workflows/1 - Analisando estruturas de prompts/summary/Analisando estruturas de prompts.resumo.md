# Analisando estruturas de prompts

## Da estrutura básica para um caso real

Depois de ver no capítulo anterior uma estrutura básica para organizar prompts, o professor passa a mostrar um prompt que ele usa no dia a dia: a **auditoria de dependências** de um projeto. O prompt verifica se as bibliotecas estão nas últimas versões, se há bibliotecas depreciadas e se alguma tem falhas de segurança. Ele escolheu esse exemplo por ser um problema real da rotina de quem desenvolve.

## A mesma estrutura fora do desenvolvimento

A estrutura não serve só para código. Se você integra uma aplicação de IA na empresa e precisa passar instruções claras a um agente que está desenvolvendo, pode usar o mesmo formato. O que importa é deixar explícitos a tarefa, os limites e o resultado esperado.

## Não existe estrutura única

O professor diz "eventualmente" de propósito: nenhuma estrutura de prompt resolve todos os problemas de um projeto ou de uma empresa. Ela é um bom ponto de partida, que precisa ser adaptado a cada contexto.

## O que vem a seguir

Nas próximas aulas, o prompt de auditoria será analisado bloco a bloco, comparando com a estrutura já vista: persona, escopo, objetivo, entrada, saída, critérios, ambiguidade e instruções negativas.
